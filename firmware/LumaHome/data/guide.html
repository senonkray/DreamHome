# Luma: облако без домашнего компьютера

Онлайн-приложение: https://luma-home-atelier-d25.abloomgnome257.chatgpt.site

## Обновление существующей платы

1. Сохраните ваш прежний `config.h` с Wi-Fi, API_KEY и назначением пинов. В публичном архиве лежит только пример: не заменяйте им свои рабочие настройки.
2. Распакуйте новый комплект. Перенесите ваш `config.h` в папку `LumaHome` рядом с `LumaHome.ino`.
3. Скачайте личный файл `cloud-config.h`, который передан отдельно в чате, и положите его туда же. В нём уже указаны адрес сервера и CLOUD_KEY. Не отправляйте этот файл другим людям и не публикуйте его.
4. Arduino IDE: установите через менеджер библиотек **ArduinoJson 6.21.5**. Выберите свою D1/ESP8266, частоту CPU **160 MHz**, корректный USB-порт. Откройте `LumaHome.ino` и загрузите скетч. В PlatformIO зависимость и частота уже заданы; для D1 mini можно выбрать соответствующее окружение.
5. Для онлайн-управления загружать LittleFS не обязательно. Если хотите пользоваться также локальным приложением, загрузите обновлённую папку data в LittleFS (теперь в ней есть transport.js).
6. Откройте опубликованный сайт → Настройки → **Облако — ESP8266 напрямую, без шлюза**. Вставьте значение CLOUD_KEY из личного файла, без кавычек, в «Ключ подключения» и нажмите «Сохранить и проверить».
7. Плата должна быть подключена к Wi-Fi 2.4 GHz с доступом в интернет. После перезапуска ей требуется получить точное время по NTP, затем установить HTTPS-соединение. Первый запуск/переподключение может занять несколько секунд.

Шлюз, домашний сервер, проброс портов и постоянный компьютер не нужны. Сайт уже содержит сервер команд; ESP8266 самостоятельно забирает их по исходящему HTTPS. Ключ API из старого config.h используется только для локального управления; в облачном режиме используйте именно CLOUD_KEY.

## Резервная Wi-Fi сеть

В config.h можно указать вторую сеть: `WIFI_SSID_2` и `WIFI_PASSWORD_2`. Если оставить их пустыми, плата работает только с первой сетью.

- Первая сеть всегда главная. При включении плата сначала 20 секунд пытается подключиться к ней и только потом пробует резервную.
- Если главная сеть пропала больше чем на 20 секунд, плата переходит на резервную.
- Если в config.h есть облачный ключ, плата раз в 30 секунд проверяет доступ в интернет. Если роутер подключён, но интернета нет 3 проверки подряд (около полутора минут), плата тоже переходит на резервную. Без облака эта проверка выключена: в чисто локальной схеме плата не уходит из домашней сети, пока та работает.
- На резервной сети плата через 1 минуту ищет главную в эфире и, как только видит её, возвращается. Если главная снова не работает, ожидание перед следующей попыткой удваивается, но не больше 10 минут.
- В резервной сети у платы другой IP. Адрес `http://luma.local/` продолжает работать, если телефон в той же сети. Текущая сеть видна в приложении: Настройки → «Обновление по Wi-Fi».
- Главная сеть должна быть видимой: скрытую сеть поиск не найдёт, и плата вернётся на неё только если пропадёт резервная.

## Обновление по Wi-Fi (OTA)

Первый раз прошивку с поддержкой OTA нужно загрузить по USB. После этого кабель не нужен: плата в той же Wi-Fi сети обновляется тремя способами. Пароль везде — `API_KEY` из config.h.

1. **Из приложения.** Откройте `http://luma.local/` или IP платы в режиме «Локально» → Настройки → «Обновление по Wi-Fi». Выберите `firmware.bin` (прошивка) или `littlefs.bin` (интерфейс): тип файла определяется сам. После загрузки плата перезагрузится, а страница обновится.
2. **Запасная страница** `http://luma.local/update`. Она хранится во flash вместе с прошивкой и открывается, даже если интерфейс в LittleFS пустой или сломан.
3. **PlatformIO без кабеля:**
   ```sh
   LUMA_OTA_KEY='ваш API_KEY' pio run -e d1_mini_ota -t upload
   LUMA_OTA_KEY='ваш API_KEY' pio run -e d1_mini_ota -t uploadfs
   ```
   Если `luma.local` не находится, замените `upload_port` в platformio.ini на IP платы. В Arduino IDE плата появится в списке портов как сетевой порт «luma».

Где взять файлы: после `pio run -e d1_mini` и `pio run -e d1_mini -t buildfs` они лежат в `.pio/build/d1_mini/` (`firmware.bin`, `littlefs.bin`). В Arduino IDE: Скетч → Экспорт бинарного файла.

- Прошивка и образ LittleFS должны быть собраны для той же платы и той же разметки flash (в PlatformIO окружение `d1_mini`), иначе раздел не совпадёт.
- Для обновления прошивке нужно свободное место размером с саму прошивку. Сейчас прошивка занимает около 490 КБ из примерно 1 МБ, так что место есть. Если прошивка станет больше, сожмите её (`gzip -9 firmware.bin`) и загрузите `firmware.bin.gz`: ESP8266 распакует её сам.
- Настройки из config.h и cloud-config.h находятся внутри прошивки. Чтобы поменять Wi-Fi или ключ, соберите прошивку с новым config.h и загрузите её. Если указать неверный Wi-Fi, плата не выйдет в сеть, и останется только USB.
- Не выключайте питание во время записи. Если оборвётся загрузка прошивки, плата продолжит работать на старой. Если оборвётся загрузка интерфейса, откройте `http://luma.local/update` и загрузите `littlefs.bin` ещё раз.
- Обновление работает только в локальной сети, через облако — нет.

## Задержки и подтверждение

- Последнее положение ползунка передаётся во время движения, очередь не накапливает старые значения.
- При временной сетевой ошибке последнее состояние повторяется до двух раз. Ошибки ключа не повторяются.
- После каждого завершённого облачного обмена плата делает паузу 400 мс. Это не гарантия задержки 400 мс: интернет, TLS-переподключение и Wi-Fi добавляют время. Первое соединение с проверкой сертификата может на несколько секунд приостановить обновление эффектов; постоянное соединение и TLS-сессия переиспользуются.
- «Ожидается ESP8266» означает, что команда записана на сервер, но ещё не подтверждена платой. Интерфейс проверяет подтверждение примерно раз в 1.5 секунды.
- Новые команды не принимаются, если плата не сообщала о себе более 12 секунд. Команды старше 30 секунд и команды до перезагрузки платы не воспроизводятся автоматически.
- Число миллисекунд в интерфейсе — время ответа API, не измеренная задержка до светодиодов.
- Wi-Fi энергосбережение в прошивке выключено: это может уменьшить сетевые задержки, но увеличивает потребление ESP8266.

## Микрофон непосредственно на плате

Поддерживается аналоговый микрофонный модуль с усилителем, подключаемый к A0 **после проверки напряжений**. У самого ESP8266 предел A0 — 1 В; разные D1/клоны имеют разные делители. Нужны точная модель платы и микрофона для выбора схемы. Не подключайте выход 5 V непосредственно к A0.

По умолчанию микрофон отключён. После проверки подключения добавьте в config.h:

```cpp
#define MIC_ENABLED 1
#define MIC_NOISE_FLOOR 8.0f
#define MIC_GAIN 6.0f
```

Загрузите прошивку заново. В приложении откройте Музыка → **Микрофон на ESP8266**. В этом режиме анализ громкости происходит на плате: интернет не передаёт звук. Ползунок чувствительности управляет усилением реакции; порог шума задаётся MIC_NOISE_FLOOR. Это реакция на амплитуду, не FFT-анализ частот.

A0 опрашивается не чаще раза в 6 мс, чтобы не мешать Wi-Fi. При работе микрофона через браузер локальный режим остаётся доступен; передача браузерного аудио в облачном режиме отключена из-за задержек.

## Проверка

Сервер и очередь команд проверены автоматическими тестами; прошивка компилируется. Работа на физической D1, аналоговый тракт микрофона и фактическая задержка света требуют проверки на вашем оборудовании. Из этой среды плата по 192.168.1.101 не ответила.

Документация по ADC и ограничениям Wi-Fi: https://arduino-esp8266.readthedocs.io/en/3.1.2/reference.html


# Luma Home · ESP8266

Комплект для одной аналоговой RGB-подсветки картины и веб-интерфейс для дома. Поддерживает несколько записей камер. Данные комнат, сцен, картины и камер сохраняются в браузере, синхронизации между телефонами нет. По умолчанию приложение работает в деморежиме. Реальное устройство требуется прошить и подключить по инструкции.

## 1. Оборудование

- NodeMCU ESP8266 (ESP-12E, 4 MB flash) или совместимая плата.
- Обычная неадресная RGB-лента с общим плюсом, как правило 12 или 24 V: проверьте маркировку вашей ленты.
- Подходящий по напряжению и току источник питания. Мощность = W/м × длина, с запасом по мощности.
- Три N-канальных логических MOSFET, рассчитанных на нужный ток и напряжение, с низким Rds(on), указанным в даташите при Vgs 2.5–3.3 V. Обычный модуль IRF520 для 3.3 V не подходит.
- По 100–220 Ω последовательно в затвор каждого MOSFET и по 10 kΩ от затвора к земле. Предохранитель в цепи питания ленты под выбранный ток и сечение проводов.
- ESP8266 питать от USB 5 V либо подходящего стабилизатора. На GPIO нельзя подавать напряжение питания ленты.

Это схема для неадресной RGB-ленты с общим плюсом; WS2812 / WS2811 требуют другой прошивки. Подключение всей ленты одним цветом: отдельные пиксели не управляются.

## 2. Соединения

| ESP8266 | Через резистор 100–220 Ω | MOSFET | Лента |
|---|---|---|---|
| D7 / GPIO13 | Gate | Drain | R |
| D5 / GPIO14 | Gate | Drain | G |
| D6 / GPIO12 | Gate | Drain | B |

Пины задаются в `config.h` (`RED_PIN`, `GREEN_PIN`, `BLUE_PIN`). Приложение показывает фактические пины платы в разделе «Схема подключения».

Микрофон (необязательно): модуль MAX9814 или MAX4466 — VCC → 3V3, GND → GND, OUT → A0. Затем `#define MIC_ENABLED 1` в config.h. У NodeMCU / D1 mini на A0 есть делитель (вход до ~3.2 В); у «голого» ESP-12 предел A0 — 1 В.

Все Source соединить с минусом источника питания ленты и GND ESP8266. Между каждым Gate и Source поставить 10 kΩ. Общий плюс ленты соединить с плюсом её источника питания через предохранитель. Не соединять 12/24 V с 3V3, USB или GPIO платы. Проверяйте расположение выводов по даташиту именно ваших MOSFET. Соединять при отключённом питании.

## 3. Настройка прошивки

Установите ArduinoJson **6.21.5** через менеджер библиотек Arduino IDE. Откройте `LumaHome/config.h`. Укажите домашнюю Wi-Fi сеть 2.4 GHz (`WIFI_SSID`, `WIFI_PASSWORD`) и случайный `API_KEY` длиной не менее 24 символов. Например, сгенерируйте ключ командой `openssl rand -hex 24`. Не публикуйте заполненный config.h.

Программа специально не запускает сервер, пока оставлен ключ-заглушка. При старте свет всегда выключен. Wi-Fi пароль, ключ и пины задаются при прошивке. При потере Wi-Fi контроллер пытается переподключиться. Если сеть недоступна при старте, ждёт её, не создавая открытой точки доступа.

### Arduino IDE

1. Установите пакет плат ESP8266 через Boards Manager. URL пакета: https://arduino.esp8266.com/stable/package_esp8266com_index.json
2. Откройте `LumaHome/LumaHome.ino`, выберите NodeMCU 1.0 (ESP-12E Module), flash 4 MB, выделите LittleFS минимум 1 MB.
3. Выберите USB-порт, соберите и загрузите скетч.
4. Установите LittleFS uploader для вашей версии Arduino IDE. Для IDE 2: https://github.com/earlephilhower/arduino-littlefs-upload . Загрузите содержимое папки `LumaHome/data` в LittleFS. Это отдельная операция от загрузки скетча.
5. Откройте Serial Monitor на 115200 baud. После соединения будет выведен локальный IP.

### PlatformIO

Из папки комплекта (там, где `platformio.ini`):

```sh
pio run
pio run -t upload
pio run -t uploadfs
pio device monitor -b 115200
```

Плата и filesystem уже настроены. Перед загрузкой проверьте config.h. Сборка с примером config.h компилируется, но требует замены ключа для запуска. `.pio` — промежуточные файлы, на ESP загружаются лишь firmware и LittleFS.

## 4. Подключение приложения

Откройте `http://<IP_из_Serial_Monitor>/` в той же домашней Wi-Fi сети. Обычно также работает `http://luma.local/` (зависит от поддержки mDNS на устройстве). В настройках выберите «Локально — приложение на ESP8266», введите ключ API из config.h и нажмите «Сохранить и проверить».

При успешном соединении интерфейс загрузит реальное состояние контроллера. Измените цвет и яркость. Статус «ESP8266 подключён» появляется только после ответа API. При ошибке команды показываются в превью, а приложение сообщает, что команда не доставлена. Ключ хранится в sessionStorage и может потребоваться повторно после закрытия браузера.

Локальная страница работает без интернета: для шрифта будет использован системный вариант, если Google Fonts недоступен. Картина, код и стили хранятся на ESP8266. Изображение пользователя сохраняется в браузере и не загружается на ESP.

## 5. Онлайн-версия — прямое облачное подключение

Для управления без домашнего компьютера используйте новый режим «Облако — ESP8266 напрямую, без шлюза». Плата самостоятельно подключается к опубликованному серверу по HTTPS. Нужна обновлённая прошивка и личный cloud-config.h. Пошаговая настройка — в CLOUD-START.md.

Старый режим «Удалённо — через HTTPS-шлюз» оставлен для существующих прокси: он не нужен для прямого облачного подключения.

## 6. Световые сцены и звук

- 6 сцен: Тёплый вечер, Романтика, Для двоих, Тусовка, Кино, Ночной свет.
- Эффекты: постоянный цвет, плавное дыхание, перелив цветов, имитация свечи. Скорость регулируется. Мерцающий стробоскоп не используется.
- Свои сцены сохраняют цвет, яркость, эффект и скорость.
- Микрофон: нажмите кнопку во вкладке «Музыка», разрешите доступ. Требуется secure context: HTTPS или localhost. Обычная страница http://IP-ESP8266 не получит доступ к микрофону.
- Аудиофайл: выберите поддерживаемый браузером файл, например MP3. Этот режим работает и на локальном HTTP. Звук анализируется Web Audio API, исходное аудио никуда не отправляется.
- На контроллер передаётся только интенсивность примерно 6 раз в секунду. При прекращении сообщений через 1 секунду он возвращается к базовой яркости. Во время музыки вкладка должна оставаться открытой. Микрофон останавливается при скрытии вкладки.
- Обычная RGB-лента светится одним цветом по всей длине; эффект радуги — смена цвета всей ленты во времени.

## 7. Таймер

От 1 минуты до 24 часов. `0` отменяет таймер. В реальном режиме время отсчитывает ESP8266, браузер можно закрыть. При перезагрузке ESP таймер сбрасывается, свет остаётся выключенным. В деморежиме таймер браузерный и не управляет физическим светом.

## 8. Камеры

Добавьте название, комнату и URL в разделе «Камеры». Поддерживаются MJPEG/изображение через `<img>` и MP4/WebM через HTML5 `<video>`. Источник должен выдавать правильный MIME type и формат, совместимый с браузером. Не любой HTTP-адрес камеры является видеопотоком.

RTSP/ONVIF не воспроизводятся напрямую: потребуется отдельный шлюз, преобразующий RTSP в MJPEG или браузерный поток. Запись, PTZ и обнаружение ONVIF в этой версии не реализованы. На HTTPS-странице нужен HTTPS-поток. Для HTTP-камер используйте локальный интерфейс; браузер может запросить доступ к локальной сети. Пароли в URL не принимаются. Используйте защищённый шлюз или существующую авторизованную сессию камеры.

## 9. API

Все вызовы требуют заголовок `X-API-Key`. Тело POST: `application/x-www-form-urlencoded`. Успешный ответ содержит `device: "luma-esp8266"`.

- `GET /api/state` — power, color (#rrggbb), brightness (0–100), speed (1–100), effect, remaining (секунды таймера), rssi.
- `POST /api/state` — необязательные color (6 hex без #), brightness, speed, power (0/1), effect (static/breathe/rainbow/candle), audio (0–100). Весь запрос валидируется перед применением.
- `POST /api/timer` — minutes (0–1440).
- Ошибки 400 — параметры; 401 — неверный ключ; 403 — Origin не разрешён.

Пример (используйте собственный IP и переменную окружения с ключом):

```sh
curl -H "X-API-Key: $LUMA_API_KEY" http://192.168.1.50/api/state
curl -H "X-API-Key: $LUMA_API_KEY" -d 'color=ff9e57&brightness=75&power=1&effect=static' http://192.168.1.50/api/state
curl -H "X-API-Key: $LUMA_API_KEY" -d 'minutes=30' http://192.168.1.50/api/timer
```

Команды не записываются во flash при каждом движении слайдера. Текущее состояние света и таймер не сохраняются после отключения питания. При подключении UI читает состояние платы. Приложение поддерживает один ESP-контроллер картины за раз, несколько камер и комнаты; массовое управление несколькими RGB-контроллерами требует расширения реестра устройств.
